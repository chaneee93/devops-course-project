# M8-4 부하 테스트 + HPA 검증 결과

## 조건
- 도구: k6 (단계별 VU 50 → 100 → 200, 총 5분 22초)
- 대상: minikube 백엔드 (course-backend), HPA CPU 50% 기준 (min 2 / max 10)
- 엔드포인트: GET /api/courses
- 접근: kubectl port-forward (로컬 18080 → 서비스 8080)

## k6 결과 (실측)
- 총 요청: 5,342건
- TPS(처리량): 16.56 req/s
- 평균 응답시간: 6.14s
- p95 응답시간: 30.08s (전체) / 9.89s (성공 응답만)
- 에러율: 10.95% (585 / 5,342)

## 해석
- 200 VU 부하에서 시스템 포화 → 응답 지연 급증(p95 30s), 에러 10.95% 발생.
- 병목 원인:
  1) port-forward 단일 터널 → 실제 TPS가 16으로 제한 (부하 전달 자체가 병목)
  2) 제한된 Pod 수 + DB 커넥션 풀 포화
- 즉 단일 인스턴스로는 고부하를 못 버티며, 이것이 HPA(자동 확장)가 필요한 이유.

## HPA 동작
- CPU 임계값 50% 초과 시 Pod 2 → N개로 scale out, 부하 해제 후 scale in.
- HPA 반응 시간: metrics 수집 주기상 약 15~30초.
- port-forward 병목으로 CPU 상승이 제한적일 때는 클러스터 내부 부하(load-gen)로 scale out 재현.

## 튜닝 메모
- CPU 임계값 50% → 70%로 올리면 scale out이 더 늦게 발생(부하를 더 견딤).
- 트래픽 특성에 맞춰 임계값·min/max·안정화 윈도우 조정.
